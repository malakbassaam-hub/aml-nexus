# AML-Nexus
**Catch the criminals. Protect everyone else.**

An AML compliance copilot prototype. It detects laundering patterns in a transaction graph (fan-in "smurfing", closed loops),
shows evidence *for and against* each suspicion, and recommends a graduated response
(Clear / Verify / Monitor via Evidence Watch / Escalate). **It only recommends; a human reviewer decides.**

> **All data is synthetic. No real customers or transactions.** Results below describe synthetic data
> generated by this repo and are not claims about real banks. A bank would need to validate on its own data and policies.

## Run
```
pip install -r requirements.txt
streamlit run app.py      # dashboard (demo scenarios in the sidebar)
```
Tests / evaluation:
```
pip install -r requirements.txt
python -m unittest discover -s tests -t .
python -m src.evaluate
```

## Honest results (synthetic data, 10 held-out seeds)
- Planted laundering accounts flagged for Monitor/Escalate: ~99.7% (worst seed 96.6%).
- Innocent accounts at freeze-level (Escalate): 0. Innocents sent to Verify: ~10 per seed; to Monitor: ~6 per seed (mostly charities and emergency fundraisers).
- A naive count-based rule at matched detection rate flagged ~35 innocents per seed, and could not reach our detection rate in 6 of 10 seeds.

## Evidence ledger: what it is and what it is not
A small naive-Bayes model whose inputs each add or subtract decibans of evidence (`python -m src.train_ledger`; weights in `docs/ledger_model.json`).
Trained on 14 synthetic seeds, cut chosen on those seeds, reported on 10 held-out seeds (`docs/ledger_results.json`):
the model flagged all 140 planted collector accounts and 0 of 194 innocent candidates; the rules flagged 139 and 58 innocents.
**Read this as a sign that the synthetic data is easy to separate, not as accuracy.** The model sees the same features as the rules, so it is a
second opinion with learned weights, not independent evidence. Closed loops are excluded (no innocent loops in the data). Real use needs the
bank's own labelled case outcomes.

## Known limits (please read)
- The data generator and the detectors were written by the same authors, so these numbers are optimistic. They show the pipeline works, not that it will work on real data.
- The slow-accumulation rule assumes the receiving account is young (<45 days). In a stress test where criminals use aged accounts, evasive and slow-drip rings are almost never flagged.
- Detection of evasive rings is sensitive to the counter-evidence cutoff (0.35 vs 0.4 changes it sharply), which is a sign of brittleness.
- Legitimate fast-payout fundraisers and campaign-style charities still reach Monitor; a human reviewer must clear them.
- Thresholds are policy parameters, not legal advice or validated limits.

## PayPal Sandbox setup
1. In the PayPal developer dashboard (Sandbox), open your app and enable **Transaction Search**; save. (If the app was already used it can take hours to activate.)
2. Streamlit Cloud: App settings > Secrets, paste the `[paypal]` block from `.streamlit/secrets.toml.example` with your **sandbox** client id/secret. Locally: copy it to `.streamlit/secrets.toml` (git-ignored).
3. Send a few test payments between sandbox accounts; they can take up to 3 hours to appear. Then use the **PayPal Sandbox** tab.
- The integration is read-only and refuses any non-sandbox URL.
- Streamlit cannot receive webhooks, so the dashboard pulls transactions instead.
- The live sandbox feed is small. Large scenarios are synthetic and are labelled as such. PayPal does not expose account age, so age-based signals are neutral on live data.

## Inspirations (inspired by, not implementations of)
- John Snow's 1854 cholera map: the money-flow map exists because a picture shows what a table hides.
- Weight of evidence (I. J. Good and Alan Turing's wartime work): evidence for and against is added up transparently, which is the idea behind the score breakdown.
- Benford's law (Newcomb 1881, Benford 1938), used in forensic accounting: used only relative to peers, because honest price points also break it.

## AI tools and models disclosure
- **Statistical machine-learning model (built in this repo):** the evidence ledger, a naive-Bayes model with Laplace smoothing, trained on synthetic data (`python -m src.train_ledger`). It gives a second opinion in decibans of evidence.
- **Graph analytics (not machine learning):** NetworkX for closed loops; rule-based detectors for fan-in and slow accumulation.
- **Large language model (optional):** Google Gemini (free tier via Google AI Studio) or Anthropic Claude write case summaries from a JSON of the case evidence. They only restate it: every number in the output is checked against the evidence, and a labelled template is shown if the check fails or no key is set. No account identifiers and no synthetic ground-truth labels are sent.
- **AI never decides.** Recommendations come from the screening logic; a human reviewer makes every decision.
- **Development:** this project was built with the help of an AI assistant (Claude) for code and review, directed and tested by the author.

## PayPal integration
OAuth2 client-credentials and the Transaction Search API (read-only, sandbox only) feed the same detectors and flow map as the synthetic scenarios. Streamlit cannot receive webhooks, so the app pulls transactions instead. The live sandbox feed is small; large scenarios are synthetic and labelled.
